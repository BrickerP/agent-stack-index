# Protocol 2026-10: Agent Stack Index, October 2026 (pilot)

Status: pilot
Rung: describe
Written: 2026-10-19 (data collected on 2026-10-15)

This is a retrospective protocol. The design was not pre-registered and some choices were made after seeing data, so every finding in this release is exploratory. It exists so that the next release starts from a written baseline.

## Direction
Rung 1, describe. We did not know which tools current models pick for common needs, so the first step was a descriptive measurement and a first look at what moves the pick.

## Goal
Which tools do AI coding models pick when they start a project from scratch, and what moves the pick: the wording, the order of candidates, or documentation in context?

Decision: whether a rung-2 experiment (controlled manipulations) is worth running, and on which categories.

## Hypotheses
None pre-registered. Questions put to the data: (1) do models share a default in each category; (2) does rewording change a model's pick; (3) does documentation in context change the pick; (4) does the order of candidates matter.

## Design
10 models from 8 labs, 29 needs. Baseline: 16 tasks (one task for 27 categories, two for 2), 3 phrasings, 4 repeats per phrasing: 1,920 answers. Duel: 5 needs, three arms (no notes; notes on three candidates in all six orders; each candidate's notes alone): 750 answers. The notes were written by us from public documentation.

## Controls
The candidates' order was rotated through all permutations in the trio arm. Raw answers are stored verbatim and a public catalog maps them to vendors afterwards. Not controlled: sampling parameters (each model ran at its route's default), the gateway (two Claude routes add a hidden system prompt), task diversity (one prompt per category).

## Sample size
Not justified in advance. Per model and category: 12 answers (4 per phrasing). Duel: 30 answers in the no-notes arm, 60 in the trio arm, 20 per candidate alone; shifts below about 20 points cannot be resolved between the first two.

## Analysis
Descriptive shares with Wilson intervals; category tiers by thresholds set after seeing the data (`[analysis]` in release.toml). Added on 2026-10-19, after a self-audit: a label-shuffle null for the wording effect, Fisher exact tests with Holm correction for the duel contrasts, and a binomial test for position.

## Validity checks
Catalog mapping: 3,669 of 3,720 picks matched by exact alias, 51 by whole-word match, none unmatched. Not done: a human audit of the mappings, a neutrality check of the duel notes, a replication on a direct provider API.

## Engineering benefit
Builders: in the settled categories an agent's default is predictable across models; elsewhere, name the tool you want, and do not rely on the order of a list you give it.

Tool makers: a tool can be picked by being read, and being listed first helps; being the default is a training outcome that is slow to change.

Harness: the story-driven report, share cards and an inference module (null models, corrected tests).

## Report
Three findings in plain words, each with the number that backs it and a label (exploratory for this release), then what it means for builders and tool makers and how sure we are.

## Deviations
- 2026-10-19: the wording statistic changed from a raw count to a count against a label-shuffle null, because the audit showed about 17 of the 31 changes are sampling noise. Duel statements changed from "held within N points" to "no detectable change".
